## 还剩 2 个（都已定位到具体机制，未修）

### 1. `plugin-host` · 「the watchdog: a worker that stops beating is terminated」

`room.state.content.cs` 在 worker 崩溃重开后从 `ef95…` 变成 `ec25…`（测试 `plugin-host.test.js:227` 要求两者相同）。

- `lobby.js:1082` 的 `sameSet` 只比较 `vs` / `cs`；
- `resolveContent`（`lobby.js:1110`）把 `replacing: room?.content` 传给 `plugins.resolve`，
  而 `cs` 由那次解析得出 —— 同一个插件 id 列表在「替换前内容不同」时会解析出不同的 `cs`；
- 但 `setPlugins`（唯一带 `replacing` 的调用方）**不在崩溃路径上**，所以还需查清是谁在崩溃后重新解析。

### 2. `lobby-integration` · 「co-op spectator removed by the host」

**服务端序列是对的**（已用日志确认）：

```
push Spec1 → push Spec2 → splice Spec1 → push Spec3
```

失败的是**测试客户端**：`test/helpers/wsClient.js` 的 `waitFor(type, pred)` 从 inbox 里取**最旧的匹配帧**
（`findIndex` + `splice`），不匹配的旧帧留在 inbox。我们在观战加入时比上游多发了一次 `room.state`，
于是「移除前的 2 人状态」残留下来，第 262 行的 `waitFor(length === 2)` 匹配到了它。

两条路：找出那次多余广播（根因），或让 `waitFor` 从「调用时刻之后」开始匹配（改 helper，影响面大）。

## 本轮修掉的关键项（供以后参考）

- **`server/net.js` 必须是我们自己的** —— 上游没有 `prepareMessage` / `sendPrepared` / `compactWire`。
- **`player/basics.js` 的 `get pool()`** —— 没有它比赛在第一次 `_rollChessSlot` 就抛错，永远停在 ROUND_START。
- **`FreezeScheduler` 要转发 `runUntil` / `runNext` / `advance`**，且 `Match.gameNow()` 要能回退到 `now()`：
  测试和日志回放会把 `m.sched` 换成只有 `now()` 的桩。
- **`CHESS_SECTIONS` 是位置契约**（`mountVNodes` 按数组下标命名块），皮肤选择器不能作为数组项，
  必须作为额外 vnode 插在 `skill` 之后。
- **`SkinSection` 取 `charId`**，不是 `chess` 记录。
- **`PUBLIC_THROTTLE = 200`** —— 测试写明的「普通更新至少间隔 200 ms」；125 会让 0.3.1 的公共视图
  在窗口内变两次。
- **删代码后要检查 JSDoc 是否闭合** —— 删 `setSkins` 副本时留下未闭合的 `/**`，
  把 `onDisconnect` / `onReconnect` / `_resync` / `onLeave` / `_quit` / `dispose` 全注释掉了，
  `node --check` 看不出来，只有投票/优先级测试会抓。
