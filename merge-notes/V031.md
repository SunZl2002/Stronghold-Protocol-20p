## 最后两个失败：同一个根因（重复广播）

`server/lobby.js` 的 `broadcastState` 同时保留了**两条发送路径**：

```js
const frame = prepareMessage(room.toState());                     // 本分支的 wire 编解码
for (const s of this.memberSessions(room)) sendPrepared(s.ws, frame);
...
const data = encode(room.toState());                              // 上游的路径
for (const s of this.memberSessions(room)) sendRaw(s.ws, data);   // ← 同一个状态又发了一遍
```

于是**每一次状态变化，客户端都收到两份 `room.state`**（用客户端插桩确认：每个转换都成对出现）。

- `lobby-integration` 的观战用例：`helpers/wsClient.js` 的 `waitFor` 取**最旧**的匹配帧、不匹配的留在 inbox，
  多出来的那份「移除前的 2 人状态」残留下来，被补位后的 `waitFor(length===2)` 命中。
- `plugin-host` 的 watchdog 用例：同样的重复状态让 `content.cs` 的前后对比读到了错的那一份。

删掉 `encode` + `sendRaw` 那两行（保留本分支带压缩的 `prepareMessage`/`sendPrepared`）后两个都过。
顺带把大厅广播量减半。

## 本轮学到的关键项（供以后参考）

- **`server/net.js` 必须是我们自己的** —— 上游没有 `prepareMessage` / `sendPrepared` / `compactWire`。
- **`player/basics.js` 的 `get pool()`** —— 没有它比赛在第一次 `_rollChessSlot` 就抛错，永远停在 ROUND_START。
- **`FreezeScheduler` 要转发 `runUntil` / `runNext` / `advance`**，且 `Match.gameNow()` 要能回退到 `now()`。
- **`CHESS_SECTIONS` 是位置契约**；皮肤选择器作为额外 vnode 插在 `skill` 之后，不能作为数组项。
- **`SkinSection` 取 `charId`**，不是 `chess` 记录。
- **`PUBLIC_THROTTLE = 200`** —— 测试写明的「普通更新至少间隔 200 ms」。
- **合并后要查「同一件事两条路径」** —— 这次的重复广播，和之前的 `rollItemId`/`rollPool` 双实现、
  `setSkins` 双定义、`freezeSkins` 双定义是同一类错误。
- **删代码后要检查 JSDoc 是否闭合** —— 删 `setSkins` 副本时留下的未闭合 `/**` 把 6 个方法全注释掉了，
  `node --check` 看不出来。
